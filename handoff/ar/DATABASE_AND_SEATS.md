# قاعدة البيانات ومخزون المقاعد

**تاريخ المستند:** 2026-11-08 · **إصدار المشروع:** `0.1.0`

## المخطط الحالي

المصدر الدقيق للأعمدة والعلاقات هو `prisma/schema.prisma`؛ ملفات migrations هي `prisma/migrations/0001_initial` و`0002_initial_setup_and_scanner` و`0003_production_slug`. هذا نموذج تنفيذ أولي ولا يعني أن كل workflow معتمد يعمل. حالة تطبيق migrations على الجهاز الحالي غير معروفة.

| النموذج | الغرض والعلاقات الأساسية حاليًا |
|---|---|
| `User` | رقم دخول الموظف واسمه وhash كلمة المرور والدور وحالة التفعيل/تغيير كلمة المرور؛ علاقات الجلسات والحجوزات والمسح والتدقيق. لا يوجد نموذج لحساب عميل. |
| `InitialSetup` | علامة إتمام الإعداد الأول مرتبطة بشكل فريد بـSuper Admin الأول. |
| `AuthAttempt` | محاولات دخول حسب مفتاح الحساب/العنوان والتوقيت لدعم الحد من المحاولات. |
| `AuthSession` | hash فريد لرمز الجلسة والمستخدم والانتهاء والإنشاء. |
| `Production` | slug فريد وعنوان ووصف وحالة؛ له عدة performances. |
| `Performance` | موعد ضمن إنتاج؛ له مقاعد وحجوزات. |
| `Seat` | `seatCode` دائم وفريد والمنطقة والصف والجانب والرقم وحالة التفعيل. لا توجد صفوف مقاعد canonical موردة. |
| `PerformanceSeat` | حالة وسعر المقعد في موعد معين، فريد للزوج `(performanceId, seatId)`، مع انتهاء hold اختياري وحجز اختياري. علاقة Ticket واحدة. |
| `Booking` | القناة والحالة والموعد وموظف/معتمد اختياري وحقول العميل/المجموعة والتصنيف والمبالغ والدفع والمهلة وتوقيتات دورة الحياة. |
| `PaymentRecord` | الطريقة والحالة والمبلغ ومراجع المزود وتفاصيل التأكيد/التحصيل ومفتاح إثبات اختياري. لا تكامل مزود. |
| `Ticket` | الحجز ومقعد الموعد الفريد وhash الرمز والحالة ووقت الإصدار. لا تنفيذ PDF/QR. |
| `TicketScan` | التذكرة وحساب الماسح والوقت والنتيجة. لا تنفيذ استرداد/تحقق الماسح. |
| `IdentityDocument` | الحجز ومفتاح التخزين الخاص والحالة وتوقيت الرفع/الحذف. لا منطق ملفات/صلاحيات. |
| `AuditEvent` | الفاعل والإجراء والكيان وبيانات قبل/بعد JSON والتوقيت. اكتمال السجل غير متحقق. |

تشمل enums: `UserRole` و`BookingChannel` و`BookingStatus` و`PaymentMethod` و`PaymentStatus` و`PerformanceSeatStatus` و`TicketStatus` و`GroupAffiliation` و`ApprovalStatus`. بعض الحالات مثل حالة الإنتاج/الموعد والهوية نصوص وليست enums مقيدة.

### العلاقات وضمانات سلامة البيانات

يدعم المخطط Production واحدًا إلى عدة Performances. يمكن ربط Seat فعلي بمواعيد مختلفة؛ ويمنع `@@unique([performanceId, seatId])` تكرار صف مخزون للمقعد والموعد نفسيهما. تساعد قيود QR hash الفريد وارتباط Ticket الفريد بمقعد موعد على النموذج المقصود. لكنها لا تنفذ وحدها الحجز الآمن أو الانتهاء أو التحقق من الدفع أو البيع الذري أو الإلغاء/الاسترداد أو منع المسح المكرر؛ يلزم منطق معاملات واختبارات. لا يمثل المخطط رمز الحجز بوصفه اعتماد الدخول.

## المقاعد canonical: لم تُحسم؛ ممنوع اختلاقها

توجد صور Hall وBalcony المعتمدة بصريًا من المالك:

- `Markramus-assets-reference/assets-reference/seat-maps/hall-approved-reference.jpg`
- `Markramus-assets-reference/assets-reference/seat-maps/balcony-approved-reference.jpg`

لم يُعثر في الملفات المفحوصة على spreadsheet/CSV/JSON canonical أو manifest موثوق لكل مقعد. الصور مراجع بصرية وليست قائمة آمنة للاستيراد. راجع `docs/developer-handoff/SEAT-MAP.md` و`docs/pre-production/03-theatre-and-seat-inventory.md` لتفاصيل الفحص المسجلة.

ما ينقص/لم يحسم: قائمة أكواد رسمية وcrosswalk لصيغتها؛ الصف/الجانب/الرقم الدقيق لكل مقعد؛ مطابقة ملصقات Hall المحجوبة والمتكررة بصريًا ومنها `JL4`؛ تأكيد أن `TOTAL U:172` المطبوعة في صورة Balcony تعني فعلًا المخزون القابل للبيع (لا يُقبل العدد بوصفه مؤكدًا)؛ تحديد معنى L/R/C من منظور الجمهور/المسرح؛ أعلام المقاعد القابلة للبيع والمحجوبة/التصويرية والفئات الأخرى؛ وتأكيد المقاعد غير النشطة وثبات الأكواد. لا تستنتج أكوادًا أو أعدادًا من الصور ولا تعدل الملصقات بالتخمين.

القرارات المعتمدة: أكواد المقاعد فريدة ودائمة؛ يجب توثيق معنى الجهات؛ لكل `Performance` مخزون مستقل؛ يمكن بيع المقعد نفسه في موعد آخر؛ Bubble مرجع فقط ولا ترحيل إنتاج معتمد. لا يحتوي مخطط المشروع على صفوف مقاعد مستوردة canonical.

## تشغيل قاعدة البيانات ونقلها بأمان

تستخدم قاعدة Compose المحلية PostgreSQL 16 على `127.0.0.1:5433`، وقاعدة `markramus_ticketing` وvolume باسم `markramus-postgres-data`. منفذ الحاوية الداخلي 5432. لا تصل هذا التطبيق بـHikCentral PostgreSQL على منفذ المضيف 5432. لا تستخدم أوامر reset/drop لحل الأعطال.

على جهاز جديد: ثبت Node.js `>=20.19.0` وnpm وDocker Desktop؛ نفذ `npm ci`؛ أنشئ `.env` جديدًا من `.env.example` مع `AUTH_HASH_SECRET` جديد؛ شغّل `START-LOCAL.bat`. يشغل السكربت خدمة Compose المسماة `db` فقط ويتحقق من صحتها، ثم يولد Prisma Client ويطبق migrations المعتمدة قبل تشغيل Next. استخدم `npm run db:validate` للتحقق من المخطط. لتغيير المخطط أثناء التطوير استخدم `npm run db:migrate` وأضف ملف migration الجديد إلى Git. تحقق من عنوان الاتصال وخذ نسخة احتياطية قبل أي migration على قاعدة موجودة.

لا يتضمن نسخ المصدر Docker named volume أو `.env` أو `node_modules` أو `.next` أو `.local-run` أو Prisma Client المولد. إذا وجب نقل سجلات محلية حالية، فيلزم إجراء backup/restore مشفر وموافق عليه كعمل منفصل؛ لا تصدر أسرارًا أو بيانات عملاء/هوية خاصة ضمن حزمة التوثيق.
